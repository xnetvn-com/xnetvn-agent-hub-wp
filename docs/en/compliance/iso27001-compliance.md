# ISO/IEC 27001 Security Standard Compliance (ISO 27001 Compliance)

> **Report on meeting information security controls under the international ISO/IEC 27001:2022 standard for xNetVN Agent Hub WP.**

---

## 1. Annex A Controls Mapping

| ISO 27001:2022 Control ID | Control Name | Technical Measures Implemented in the Project |
|---|---|---|
| **A.5.15** | Access control | Fine-grained authorization intersecting WordPress User Permissions $\cap$ API Key Scope $\cap$ Site Ceiling $\cap$ Toolset. |
| **A.5.16** | Identity management | Identification based on the owner's WordPress account; each API key belongs exclusively to one individual. |
| **A.5.17** | Authentication information | Use random 256-bit secrets generated by `random_bytes()`, hashed with `HMAC-SHA256` and an independent Pepper. |
| **A.8.9** | Configuration management | Security configuration is centrally managed through `WpSiteSettings`, with safe defaults (Secure by Default). |
| **A.8.15** | Logging | The `*_audit` table records every MCP request, including `request_id`, UTC time and execution outcome. |
| **A.8.20** | Network security | Require HTTPS/TLS; strictly validate the Origin header against CSRF and DNS Rebinding. |
| **A.8.24** | Use of cryptography | Use standard PHP/OpenSSL cryptographic functions (`hash_hmac`, `hash_equals`, `random_bytes`), without inventing cryptography. |
| **A.8.25** | Secure development lifecycle | Apply TDD, automated CI/CD, PHPCS WordPress checks and PHPStan Level 8 static analysis without a baseline. |

## 2. Independent Row-Level Locking & Transaction Integrity Controls

- Meet Data Integrity control requirements: Key rotation uses atomic InnoDB transactions with the row-locking statement `SELECT ... FOR UPDATE`, ensuring partial states or lost keys never occur during an abrupt system failure.
