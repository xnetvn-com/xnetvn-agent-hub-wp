## Version-bound compatibility

The installed wp-env still imports simple-git as a CommonJS callable. Version4 provides the named `simpleGit` export, so a direct security override alone fails before cloning. The compatibility test reproduced that TypeError before correction.

`bin/prepare-wp-env.cjs` validates the reviewed wp-env boundary and never rewrites the installed package. It requires the exact pinned version, a project-local non-symlink install, and the reviewed named `simpleGit` import in `lib/download-sources.js` and `lib/runtime/docker/download-wp-phpunit.js`. A different version, a symlinked install or an unexpected import shape fails instead of accepting an unreviewed dependency. The guard does not disable or alter simple-git's unsafe-operation protections.

Normal `npm ci` invokes the project's postinstall validation. When scripts are intentionally disabled, run `npm run tooling:prepare` before using wp-env. `npm run test:tooling` also validates the pinned installation, then tests YAML dump/load plus the Git APIs wp-env uses: clone with options, cwd, checkIsRepo, fetch, checkout, reset and sparse-checkout/raw. Both native and library Git calls use the same minimal environment, omit caller home/config/template/editor/repository overrides, and disable system configuration with a fixed flag. The library allowlists only that fixed flag; unsafe operation allowances stay disabled. An inherited-GIT override regression also passed. Its repositories are fresh disposable local fixtures; it starts no containers/database/browser, contacts no remote Git server and changes no project/reference repository history. CI's audit job runs the contract before auditing.

These API checks complement the hosted wp-env integration matrix. The replacement graph is not accepted as hosted-compatible until the new required CI jobs actually finish. Future wp-env upgrades require reviewing the installed dependency map and the guarded import shape, updating the pinned version and the lockfile, and repeating both contract and hosted checks. Do not relax audit severity or suppress advisories to get a green result.
