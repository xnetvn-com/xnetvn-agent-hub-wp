## 🌟 Release Summary

Version **v1.0.0** is the first 1.0 release of xNetVN Agent Hub WP. It ships everything that was developed after the v0.1.0 foundation: six private ability packs, user-owned keys with per-key scope, audit and privacy tooling, the administration screens and the guarded MCP transport. The display name changed to **xNetVN Agent Hub WP**; the plugin slug, main file, folder and text domain stay `xnetvn-agent-hub-wp`, so an existing installation upgrades in place.

The product still requires the separately installed official MCP Adapter 0.7.x and authenticates MCP clients with bearer keys only. This release does not implement OAuth and registers no public abilities.

**Verification status:** automated integration/network/HTTP, UI P13, lifecycle/upgrade/uninstall and Plugin Check 0 errors passed on the frozen runtime artifact. Manual WCAG/screen-reader, hosted CI, real MCP clients, WordPress.org review and production remain unverified.

## 🚀 Implemented Capabilities

### 1. Private Ability Packs

62 private abilities across six packs: system (5), content (19), taxonomy (9), media (7), comments (10) and users (12). Every ability has a tier, a toolset, a visibility capability, annotations and a strict input schema, and every output passes the shared output pipeline before it reaches the client.

### 2. User-Owned Keys and Scope

Each key belongs to one WordPress user and can only narrow that user's current capabilities. Tier ceiling, toolsets, explicit scope and site settings are checked on every request, the `admin` tier is off by default, and the plaintext secret is shown once while only an HMAC-SHA256 hash with a separate per-site pepper is stored.

### 3. Transport Separation and Guards

The MCP route `/wp-json/xnetvn-agent-hub-wp/mcp` accepts bearer keys only and rejects cookies; management REST accepts a login cookie plus a `wp_rest` nonce only. HTTPS, exact route matching, Origin checks, request size limits and per-key and per-IP rate limits are enforced before work starts.

### 4. Audit, Privacy and Administration

Each request can write one audit row with metadata only: no argument values, bearer tokens, passwords, hashes or cookies. Retention defaults to 90 days, IP masking is available, and the plugin registers a personal data exporter and eraser. Administrators get overview, keys, activity, tools, settings and connection pages, and every user creates their own keys on the profile page.

### 5. Packaging and Requirements

The release ZIP is built and verified through `composer build` and otherwise carries only runtime paths; `composer.json` is included and still records development-only metadata that is not loaded at runtime. The ZIP is checked before publication. Two builds from the same source are content-identical; the archive SHA-256 can differ because ZIP entry timestamps are not normalized. The plugin requires PHP 8.2, WordPress 6.9 or later and the official MCP Adapter 0.7.x.
